## Solution Overview

### Approach
Adapt the existing `generate-test-vectors.sh` pipeline for Zisk:
1. Build pil2-stark C++ with `CAPTURE_TEST_VECTORS` flag (adds stderr JSON + `.proof.bin`)
2. Build `libzisk_witness.so` from `zisk-for-spec/` at v0.15.0
3. Run `proofman-cli prove` to generate per-AIR proofs + captured internal state
4. Package outputs via `create-test-vectors.py` into test fixture JSON + binary files

### Key Components
1. **Proving key** (`zisk-for-spec/provingKey/`): Per-AIR starkinfo, expression bytecode,
   constant polynomials, and Merkle trees. Generated by `pil2-proofman-js` setup.
2. **Witness library** (`zisk-for-spec/target/release/libzisk_witness.so`): Generates
   witness traces from an ELF + input. Built from zisk v0.15.0.
3. **Instrumented prover** (`pil2-proofman/target/release/proofman-cli`): Standard prover
   with `CAPTURE_TEST_VECTORS` flag that emits internal state as JSON on stderr and writes
   `.proof.bin` files alongside JSON proofs.
4. **Test fixtures** (`executable-spec/tests/test-data/zisk-*.json` + `zisk-*.proof.bin`):
   Consumed by Python E2E tests.

## Implementation Tasks

### CRITICAL IMPLEMENTATION RULES
1. **DO NOT modify `zisk/`** (symlink to zksyncos branch). All Zisk work happens in `zisk-for-spec/`.
2. Changes to `zisk-for-spec/Cargo.toml` are acceptable (e.g., local path overrides for pil2-proofman).
3. CPU proving only — `CAPTURE_TEST_VECTORS` instruments the C++ CPU code path.
4. Use `input_one_segment.bin` (smallest input) to minimize proving time.
5. The `--elf` flag is defined on proofman-cli but NOT wired to `generate_proof()`. ROM data must be prepared separately via `cargo-zisk rom-setup` or by building `cargo-zisk prove` against local pil2-proofman.
