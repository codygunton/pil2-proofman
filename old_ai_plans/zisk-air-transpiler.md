# Zisk AIR Support: TAC-to-Python Transpiler Implementation Plan

## Executive Summary

Upgrade the Python executable spec to support Zisk's ~25 RISC-V AIRs by building a **TAC-to-Python transpiler** that reads the compiler-generated bytecode (`expressionsinfo.json` / `verifierinfo.json`) and produces Python constraint/witness modules following the existing patterns. The transpiler is a one-time bootstrap tool: once tests pass, the generated code is aggressively simplified into readable spec-quality Python while maintaining the byte-identical test invariant.

**Why a transpiler (not a runtime interpreter)?** The spec's purpose is readability. The transpiler produces static Python files that can be inspected, diffed, and manually simplified. A runtime interpreter would be a black box.

**Why not hand-write?** Zisk has ~25 AIRs with thousands of constraints (Keccak alone has 1600+ bit-level constraints). Hand-translation is infeasible. The transpiler automates the mechanical step.

## Goals & Objectives

### Primary Goals
- Transpiler produces constraint/witness modules for the 3 existing test AIRs that pass all 164 tests byte-identically
- Incrementally extend to support public inputs, custom commits, then full Zisk AIRs
- Each generated module is a starting point for human simplification

### Secondary Objectives
- Eliminate the need for hand-written per-AIR modules for future AIRs
- Exercise untested protocol code paths (public inputs, custom commits)
- Establish per-AIR unit test infrastructure for Zisk

## Solution Overview

### Data Flow
```
PIL source
  |  (pil2-compiler + pil2-proofman-js — already exist)
  v
expressionsinfo.json + starkinfo.json
  |  (new transpiler tool)
  v
constraints/<air>.py + witness/<air>.py
  |  (existing test infrastructure)
  v
byte-identical proof comparison
  |  (human simplification pass)
  v
readable executable spec
```

### Key Components
1. **TAC Parser** (`transpiler/tac_parser.py`): Parses expressionsinfo.json `constraints[]`, `expressionsCode[]`, `hintsInfo[]` into IR
2. **Name Resolver** (`transpiler/name_resolver.py`): Maps numeric TAC IDs to human-readable names via starkinfo.json (`cmPolsMap`, `challengesMap`, `constPolsMap`)
3. **Constraint Codegen** (`transpiler/constraint_codegen.py`): Generates `ConstraintModule` subclass from individual constraint programs
4. **Witness Codegen** (`transpiler/witness_codegen.py`): Generates `WitnessModule` subclass from `im_col`, `gsum_col`, `gprod_col` hints

### Architecture Decision: Transpile Individual Constraints (not combined expression)

The `expressionsinfo.json` has two representations:
- `constraints[]`: Individual constraint programs with boundary info → **use this**
- `expressionsCode[cExpId]`: Single combined expression with all constraints pre-multiplied by zerofiers and vc powers

We transpile from individual constraints because:
- Produces code structurally identical to the hand-written modules
- Each constraint can be understood, named, and simplified independently
- Uses existing `_combine_constraints(constraints, vc)` for combination
- The combined expression produces an unreadable monolith

### Expected Outcomes
- A `transpiler/` package in executable-spec that generates constraint/witness Python from compiler output
- Generated modules for the 3 test AIRs passing all 164 tests
- A path to supporting any pil2-compiled AIR (including Zisk) without hand-written modules

### Execution Plan

#### Group A: Core Transpiler (Execute in sequence — each builds on prior)

- [ ] **Task #1**: Build TAC parser and name resolver
  - Folder: `executable-spec/transpiler/`
  - Files: `tac_parser.py`, `name_resolver.py`, `__init__.py`
  - **TAC Parser** reads expressionsinfo.json, produces:
    - `TacConstraint` list from `constraints[]` section (each has: `code[]` of instructions, `boundary`, `line`, `stage`, `im_pol`)
    - `TacExpression` list from `expressionsCode[]` section (each has: `exp_id`, `code[]`, `stage`)
    - `TacHint` list from `hintsInfo[]` section (each has: `name`, `fields` dict)
  - **Name Resolver** reads starkinfo.json, builds lookup tables:
    - `cm_map: dict[int, tuple[str, int]]` — cm ID → (column_name, array_index) from `cmPolsMap`
    - `const_map: dict[int, str]` — const ID → name from `constPolsMap`
    - `challenge_map: dict[int, str]` — challenge ID → name from `challengesMap`
    - `agv_map: dict[int, str]` — airgroup value ID → name from `airgroupValuesMap`
  - **Operand resolution**: `resolve_operand(TacOperand) -> str`
    - `cm` id=3, prime=0 → `ctx.col('d')` (via cmPolsMap lookup)
    - `cm` id=3, prime=1 → `ctx.next_col('d')`
    - `cm` id=3, prime=-1 → `ctx.prev_col('d')`
    - `const` id=0 → `ctx.const('__L1__')`
    - `challenge` id=0 → `ctx.challenge('std_alpha')`
    - `number` value="1" → `FF3(1)` or field constant
    - `tmp` id=25 → `t25` (local variable)
    - `airgroupvalue` id=0 → `ctx.airgroup_value(0)`
  - Array columns: cmPolsMap entries with same `name` but different positions → `ctx.col('k', 0)`, `ctx.col('k', 1)`, etc.
  - TAC instruction format: `{op: "add"|"sub"|"mul", dest: {type, id, dim, prime}, src: [{...}, {...}]}`
  - Input files for validation:
    - `/home/cody/pil2-proofman/pil2-components/test/simple/build/provingKey/build/Simple/airs/SimpleLeft/air/SimpleLeft.expressionsinfo.json`
    - `/home/cody/pil2-proofman/pil2-components/test/simple/build/provingKey/build/Simple/airs/SimpleLeft/air/SimpleLeft.starkinfo.json`

- [ ] **Task #2**: Build constraint code generator
  - Folder: `executable-spec/transpiler/`
  - File: `constraint_codegen.py`
  - Input: Parsed TAC constraints + name resolver
  - Output: Python source string for a `ConstraintModule` subclass
  - Generated code structure:
    ```python
    class {AirName}Constraints(ConstraintModule):
        def constraint_polynomial(self, ctx):
            # Challenges
            alpha = ctx.challenge('std_alpha')
            # Columns (hoisted from all constraints)
            a = ctx.col('a')
            # Constants
            L1 = ctx.const('__L1__')
            # Constraints
            constraints = []
            # Constraint 0: {source_line}
            t25 = d * alpha
            t26 = t25 + c
            ...
            constraints.append(t_final)
            # Constraint 1: ...
            return self._combine_constraints(constraints, vc)
    ```
  - Key logic:
    1. Scan all constraint instructions to collect unique operand references
    2. Group by type (challenges, stage-1 cols, stage-2 cols, constants, airgroup values)
    3. Emit variable declarations at top
    4. For each constraint, emit TAC instructions as Python assignments
    5. Emit `_combine_constraints(constraints, vc)` at end
  - Handle `number` operands: emit as field constants (needs FF/FF3 import)
  - Handle `dim`: ignored for code gen (galois handles promotion), but useful for comments
  - Handle all 3 `boundary` types present in test AIRs: `"everyRow"` (all current tests)
  - Reference pattern: `/home/cody/pil2-proofman/executable-spec/constraints/simple_left.py`

- [ ] **Task #3**: Build CLI entry point
  - Folder: `executable-spec/transpiler/`
  - File: `cli.py`
  - Usage: `python -m transpiler <expressionsinfo.json> <starkinfo.json> --output-dir <dir>`
  - Or batch mode: `python -m transpiler --air-dir <path/to/air/> --output-dir <dir>`
  - Generates both `constraints/<name>.py` and `witness/<name>.py`
  - Snake-case file naming from AIR name (e.g., `SimpleLeft` → `simple_left_generated.py`)

- [ ] **Task #4**: Build witness code generator
  - Folder: `executable-spec/transpiler/`
  - File: `witness_codegen.py`
  - Input: Parsed hints (`im_col`, `gsum_col`, `gprod_col`) + expressions + name resolver
  - Output: Python source string for a `WitnessModule` subclass
  - **im_col hints** (SimpleLeft has 6):
    - `reference`: destination cm ID (e.g., cm16 = im_cluster[0])
    - `numerator`: tmp ID in an expressionsCode entry
    - `denominator`: tmp ID in an expressionsCode entry
    - Generated: `im_cluster[0] = numerator_expr * batch_inverse(denominator_expr)`
    - Must find which `expressionsCode` entry computes the referenced tmps
  - **gsum_col hints** (SimpleLeft has 1):
    - `reference`: destination cm ID (cm15 = gsum)
    - `numerator_air` / `denominator_air`: combined air contribution tmps
    - `numerator_direct` / `denominator_direct`: direct term (0/1 = no direct numerator)
    - `result`: airgroup value ID for the cumulative result
    - Generated: cumulative sum via `_compute_cumulative_sum()` from base class
  - **gprod_col hints** (Permutation1_6 has 1):
    - Same structure as gsum_col but cumulative product
    - Generated: `_compute_cumulative_product()` from base class
  - Sub-expression tracing: For `im_col` hints, find the expressionsCode entry whose tmp range covers the referenced tmp IDs, transpile that sub-expression up to the target tmp
  - Reference pattern: `/home/cody/pil2-proofman/executable-spec/witness/simple_left.py`
